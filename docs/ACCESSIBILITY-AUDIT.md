# Accessibility audit: visas.com.py static site

Date: 2026-10-01. Scope: the built HTML (53 pages: 44 `lang="es"`, 9 `lang="en"`, including `404.html`, `gracias.html`, `en/thank-you.html`, `lp/visa-americana/` and the two `lib/forms/*.html` form pages), `assets/css/site.css`, `assets/js/site.js`, and the form fallback in `lead-forward.php` where it affects error messaging.
Method: static analysis only. A Python HTML-parser script and a WCAG contrast calculator were run from the scratchpad (`audit.py`, `contrast.py`, `hero.mjs`). No browser, screen reader or visual rendering was used, so items marked "verify" need a quick manual check. Target standard: WCAG 2.2 AA.
No file other than this one was edited.

## What already passes (no action needed)

- One `<h1>` per page, no skipped heading levels, no empty headings, on all 53 pages.
- Exactly one `<header>`, `<main id="main" tabindex="-1">`, `<footer>` per page; every `<nav>` has a distinct `aria-label`; skip link ("Saltar al contenido" / "Skip to content") is the first element on all pages and targets `#main`; no duplicate ids.
- 55 `<img>`: all have non-empty descriptive alt, `width`/`height`, `decoding="async"`; hero is `eager` + `fetchpriority=high`, the rest `lazy`. No image sits inside a link. All inline SVG is `aria-hidden` or inside an `aria-hidden` parent.
- No link text is only "aquí" / "leer más" / "click here". Repeated "Ver detalle ↗" cards carry `aria-label="Ver detalle: <title>"` (label-in-name satisfied).
- `target="_blank"` is only used on WhatsApp menu options and all have `rel="noopener"`.
- Tables (2): `<caption>`, `<thead>`, `scope="col"` / `scope="row"`; the wide one is in a focusable `role="region"` scroller.
- Form (contact): every control has an implicit `<label>`, required state is stated in text and with `required`, sensible `autocomplete`/`inputmode`/`type`, inputs are 48px high with 16px font.
- WhatsApp intent dialog and mobile menu use native `<dialog>.showModal()`: focus is trapped, background is inert, Escape closes, `aria-expanded` is set on open and reset on close, focus returns to the trigger, labelled via `aria-labelledby`/`aria-label`.
- Desktop dropdowns are `<details>/<summary>` (keyboard operable natively), Escape closes and returns focus to the summary, outside click closes.
- Reduced motion is handled for every animation and transition in the CSS (`float`, `.reveal`, route arcs, FAQ toggle, hover transforms, sheet animation, smooth scroll) and in JS (no reveal-observer when reduced).
- `viewport` meta does not block zoom; `lang` is set on `<html>` on every page.
- Global `:focus-visible { outline: 3px solid var(--sky); outline-offset: 4px }`; no `outline: none` except programmatic `#main:focus`.

## Other items checked

- Buttons vs links: real `<button>` for burger, close buttons, consent, submit and print; links for all navigation; no `href="#"` links. Only the WhatsApp trigger is a link behaving as a button (finding 8).
- Form labels: all visible controls labelled; the honeypot (`aria-hidden`, `tabindex="-1"`, `autocomplete="off"`) is correctly excluded from AT. The `#form-result` region (`role="status"`, `tabindex="-1"`) receives focus on success, which is good. Submit button text changes to "Enviando..." and disables during the request; focus is then moved by every outcome path (field, error box, result), so no focus loss.
- Touch targets elsewhere: `.button` 52px, burger/close 48px, footer links 44px, nav links 44-48px, TOC links 48px, consent buttons 48px, mobile bar buttons 52px. Only the items in finding 10 are tighter.
- Scrollable regions: `.comparison-wrap` has `tabindex="0"` and a label; `.guide-toc` (sticky, `overflow-y:auto`) is reachable through its links.
- Zoom/reflow: no fixed pixel widths on text containers; `.cost-table` uses `table-layout: fixed` with wrapping, `.comparison` scrolls inside its own region.

## Fix first (summary)

1. Finding 3: make the invalid-field state visible (`[aria-invalid]` CSS) and mark/focus the field in the no-JS fallback; it is the only level-A gap and sits on the conversion path.
2. Findings 1 and 2: two small CSS appends (focus colour on dark sections; darker `--stamp-text` for eyebrow/hover text on paper-2). They fix every contrast failure measured.
3. Finding 4: check the home hero text on a 375px phone and, if confirmed, add the flat `.80` overlay under 1000px.
4. Findings 5 and 6: restore `aria-describedby` handling in `showError`, and add `lang` / `aria-label` to the EN/ES switch and the English footer links (build-source edits, then rebuild).
5. Finding 7, then the Low items: `scroll-padding-bottom` for the fixed bar, then the JS/CSS polish (8-18) in any order; none changes layout or SEO-relevant markup, except finding 12 (alt text) which should be applied cautiously.

Counts: High 3, Med 4, Low 11 (18 findings). Pages with zero structural issues: all 53.
